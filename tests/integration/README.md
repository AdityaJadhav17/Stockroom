# Integration tests

Use xUnit and `WebApplicationFactory` from ASP.NET Core MVC Testing for HTTP handlers and authorization. Use SQLite for constraints, conditional writes, and transaction rollback. `StockroomFactory` hosts the application against a seeded temporary SQLite file for each test and supplies test-only seed passwords.

Give each test an isolated database. For a competing-write scenario, connect separate contexts to the same temporary database file and coordinate the operation starts. Inspect the final quantity, status, and history. Reject unhandled lock errors as failures.

Run the cases:

```powershell
dotnet test --project tests/integration/Stockroom.IntegrationTests.csproj --configuration Release
```

Current status: 165 cases pass on Windows. `SecurityEventLoggingTests` covers the security events for failed sign-ins, lockout, sign-in and sign-out, login throttling, page authorization denials, and service permission refusals, and checks that no log entry contains a password, cookie or token value, or form field. `PasswordHashingTests` covers the configured PBKDF2 iteration count and the upgrade of an older, lower-iteration hash at sign-in. `TheoryDataTests` keeps passwords out of theory arguments, which appear in test names and CI reports. `SecurityHardeningTests` covers the security headers, revocation of copied cookies at logout and the warning when revocation fails, immediate role removal, login throttling including the window boundary and the minimum time for one client to reach the lockout, the generic page when authentication cannot reach the database, and the secure antiforgery cookie over HTTPS. `ErrorHandlingTests` covers the controlled database-error message, logged details, the error page for unhandled database errors, and the 404 and 400 pages. On Linux, two Windows-only cases that hold the database file open or locked are skipped. `AuthenticationTests` covers T-01 and the absence of registration and password-recovery pages. `SeedTests` covers role assignment and seed reruns on the base dataset. `DemoDataTests` covers the full demo dataset: documented contents, stock reconciliation, request histories by status, complete-dataset comparison across reruns (T-14), reruns on a pre-M4 database, reset to the predictable dataset, refusal outside Development, refusal of unsupported or locked targets, pooled connections to other databases left open by reset, and missing or rejected seed passwords that stop reset before the database file changes (T-15). `SchemaConstraintTests` covers stock-movement CHECK constraints and the receipt index. `PurchaseServiceTests` covers T-05 through T-09 and T-11 for receipt, including competing reviews and receipts on separate connections to one file, refuses Member actors for manager actions and Manager actors, including dual-role accounts, for purchase creation, and resolves request and history visibility from database roles. `StockServiceTests` covers T-10, T-11 for issues, T-12 with two synchronized one-unit issues against one remaining unit, member denial, member-invisible movement history, and T-13 through a new unpooled connection. `LockContentionTests` holds the write lock on another connection past a one-second timeout for create, approve, reject, receive, and issue, and verifies the retry message and unchanged data. `PurchaseWorkflowHttpTests` and `StockAndHistoryHttpTests` cover login redirects, inventory search and empty state (T-03), low stock (T-04), form validation, request ownership, member, manager, or dual-role access to the wrong actions (T-02), and history visibility, ordering, empty state, and the absence of edit or delete forms (T-13).
